REFERENCE NOTE

A checksum match is not a safety verdict.

SHA-256 is useful for comparing file bytes. The part that matters next is where the expected hash came from.

SHA-256File integrityFieldKit
By JustinNote added Nov 12, 20263 min read
WHAT THIS NOTE IS BASED ONConnected to archives and checksums in my Linux Loadout, and to the working HashCheck utility in FieldKit. This is a short reference note, not a report about a separate lab.

Start with the question

A checksum answers a narrow question: do these bytes produce the expected fingerprint? It does not tell me whether I should run a program or trust the person distributing it.

KEEP THE DISTINCTIONMatching a trusted SHA-256 checksum is evidence of file integrity. It is not a malware scan, a signature check, or proof that the original file was safe.

A small example with exact bytes

These commands are a reproducible example. printf sends the five bytes hello without a trailing newline, then sha256sum calculates their SHA-256 digest.

SHELL / SAFE LOCAL EXAMPLE
printf %s hello | sha256sum
EXPECTED SHA-256
2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824

A file containing hello followed by a newline has different bytes and a different digest. When comparing results, first make sure the input is really the same.

Where trust enters the comparison

  • Get the expected checksum from a source you trust, such as the publisher's authenticated release channel.
  • Calculate the checksum of the file you actually downloaded.
  • Compare every character. If it differs, stop and investigate instead of treating it as close enough.
  • If an attacker can replace both the file and the checksum you use, a matching result does not solve that trust problem.

How this connects to FieldKit

HashCheck reads a file locally with the File API and passes its bytes to crypto.subtle.digest using SHA-256. It checks that an expected digest has 64 hexadecimal characters and compares it without treating uppercase and lowercase letters as different.

Web Crypto digest is not streaming: the whole file must be in memory. FieldKit caps files at 50 MB (50,000,000 bytes) and explains that limit. Files and hashes are not uploaded or saved as input history.

What to keep in mind

The useful habit is to separate byte equality from trust. A checksum is one check in a workflow, not permission to skip the other checks.
